## Diff summary
The grid's `auto-fill` template means the column count varies with viewport + density, so the up/down step is read from `offsetTop` of children rather than hardcoded. Focused-id falls back to the first item when stale (after deletes / new docs). Text-input target guard mirrors the existing global keydown handler in `+page.svelte` so the label-edit `<input>` keeps its arrow keys for cursor movement. Reviewer should sanity-check that synthesizing `new MouseEvent('click', { shiftKey })` to feed `onselect` doesn't collide with `+page.svelte:handleSelect` — that handler only reads `event.shiftKey`, so the synthetic event is sufficient.

## Followups
- Shift+arrow extends via `selectRange`, which mutates `lastSelectedId` to the new endpoint each step. That matches existing Shift+click semantics but means pulling the selection back (Shift+ArrowLeft after Shift+ArrowRight) doesn't shrink the range — it just sets a new anchor. Acceptable parity for now; a follow-up could add a fixed-anchor extension mode if real users complain.
- The grid `<div>` is now a focus host with arrow handling but no ARIA role; svelte-ignore suppresses the warning rather than adopting `role="listbox"`/`role="option"` semantics. Worth a future pass to upgrade to proper listbox semantics with `aria-multiselectable` and `aria-selected` per thumbnail — that would also let screen readers announce selection state.
