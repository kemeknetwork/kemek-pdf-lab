## Picked (and why)
Pinned the "all targeted pages deleted before export" path as a single
integration test in the existing `export pipeline — merge then watermark` block.
The two halves were already pinned in isolation — the resolver returns `[]` when
no target survives (`operator.test.ts:233`) and applyWatermark treats `[]` as
"no pages" (`watermark.test.ts:261`). What was missing is the *composition*: the
real user flow (scope the watermark to some pages, delete exactly those, export
the rest) threaded resolver → mergePdf → applyWatermark. This uniquely guards the
dangerous `[] → undefined` regression at the wire between resolver and engine —
a refactor making "no survivors" return `undefined` (= stamp all) would pass both
isolated unit tests yet silently stamp every page; only the composed test catches
it. STATE explicitly asked to pin this silent-but-correct behavior.
