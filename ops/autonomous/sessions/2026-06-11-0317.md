## Picked (and why)
Item 4, a third boundary. Auditing all four test files against their sources,
the only genuine gap left is that **no test anywhere drops a 0-byte file** —
every "bad body" fixture is >= 5 bytes and sails past the `bytes.length >= N`
length guards in `isPdfMagic` / `detectImageMime`. An empty file is the single
most common real-world malformed drop (a still-syncing file, a touched
placeholder, an empty export), and it's the one input that actually exercises
the under-length short-circuit on the user-facing drop path. The failure mode if
a guard regressed — an exception escaping the `validateFiles` loop and taking the
whole multi-file drop down — is exactly the "costs a user time" bar item 4 names.
Distinct input class, distinct branch (final fallthrough, not the try/catch the
corrupt-image test covers). One focused test, all assertions load-bearing. The
named items 1/2/3/5 are confirmed drained; this is the last clearly-valuable
boundary, so the loop should converge after it.
